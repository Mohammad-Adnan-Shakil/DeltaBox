# Contributing to DeltaBox

Thank you for your interest in contributing to DeltaBox! We welcome contributions from the community.

## How to Contribute

### Reporting Bugs

- Ensure the bug was not already reported by searching on GitHub under [Issues](https://github.com/Mohammad-Adnan-Shakil/DeltaBox/issues)
- If you're unable to find an open issue addressing the problem, [open a new one](https://github.com/Mohammad-Adnan-Shakil/DeltaBox/issues/new)
- Include a clear title, description, steps to reproduce, expected behavior, and actual behavior
- Add relevant labels (bug, enhancement, etc.)

### Suggesting Enhancements

- Open a new issue with the `enhancement` label
- Provide a clear description of the proposed feature and the motivation behind it
- If possible, include examples of how the feature would work

### Pull Requests

1. Fork the repository and create your branch from `main`
2. If you've added code, add tests that cover your changes
3. Ensure the test suite passes
4. Make sure your code lints
5. Issue that pull request

### Commit Messages

Use conventional commit format: `type(scope): description`

Examples:
- `feat(ai): add qualifying-based feature to prediction model`
- `fix(frontend): correct driver card alignment on mobile`
- `chore(deps): update spring boot to 3.2.5`

### Code Style

- **Java:** Follow Spring Boot conventions, use meaningful names, write Javadoc for public APIs
- **React:** Functional components with hooks, no class components
- **Python:** Follow PEP 8, use type hints
- **CSS:** Use Tailwind utility classes, avoid custom CSS when possible
